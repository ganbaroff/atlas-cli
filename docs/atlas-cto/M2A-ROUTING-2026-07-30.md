# M2A — objective routing (2026-07-30)

Package M2A per `ATLAS-MASTER-PLAN.md`: "pure model-free route predicates,
immutable objective T3 triggers, and deterministic repeated-input results."
Implemented in `src/atlas/cost-router-classify.ts`, extending (not
duplicating) the M1 durable record in `src/atlas/cost-router-state.ts`.

## Predicate table (ordered, first match wins)

`classifyRoute(task: RouteTaskInput)` walks this table over objective,
caller-declared boolean/string fields — never free-text/NLP guessing:

| order | predicate name | route | test |
|---|---|---|---|
| 1 | `t0-deterministic-tool-named` | T0 | `deterministicTool` is a non-empty string |
| 2 | `t1-sanitized-web-research-only` | T1 | `needsWebResearch === true` |
| 3 | `t2-bounded-local-worker` | T2 | `needsLocalWorker === true` |
| 4 | `t3-premium-reasoning-requested` | T3 | `needsPremiumReasoning === true` |

Cheapest routes are checked first, so a malformed task with more than one
flag set resolves to the cheaper route rather than escalating. No entry in
the table calls a model, a provider, or performs network/filesystem I/O —
verified by a `fetch` spy in the test suite. If no predicate matches, the
task is `unclassifiable` and is refused rather than defaulted to any route
(most importantly, never silently to T2).

## Four mandatory objective T3 triggers

`T3_TRIGGERS` (owned in `cost-router-state.ts` since it is part of the
durable premium-owner record, imported by the classifier):

- `architecture`
- `conflict-resolution`
- `critical-implementation`
- `independent-verification`

A task that matches the T3 predicate without carrying one of these four
exact trigger values is refused with `RouteRefusalError('t3_trigger_missing')`
naming route `T3`. `premiumOwnerSchema` in `cost-router-state.ts` gained an
optional `trigger` field so the accepted trigger is recorded on the same M1
durable record that already tracks `activePremiumOwner` — no parallel router,
no second record.

## Guard 1 — escalation cap (one per task, on the M1 record)

Enforced by the M1 record itself: `acquirePremiumOwner` throws
`task_escalation_exhausted` when a taskId that already consumed
`escalationLedger[taskId] = 1` tries to acquire again. `acquireT3RouteOwner`
in the classifier module is a thin composition — it resolves the route,
validates the trigger, then calls `acquirePremiumOwner` unchanged. No new
ceiling logic was added; M2A only wires the accepted trigger onto the
existing ceiling.

## Guard 2 — unavailable route refuses, never downgrades

`RouteAvailability` (`{ T0, T1, T2, T3 }`, defaulting to
`DEFAULT_ROUTE_AVAILABILITY = { T0: true, T1: false, T2: true, T3: true }`)
folds "route disabled by policy" and "provider unavailable" into one signal,
since M2A is offline-only until the M5/M6 live gates. `T1` (sanitized public
web research) defaults off per the master plan ("research stays off until
its live gate"). `checkRouteAvailability` refuses with
`RouteRefusalError('route_disabled', route)` and the caller never falls
through to another route — proven by a spy asserting no local-model
invocation occurs on refusal.
