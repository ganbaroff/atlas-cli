## 6. Prime Agent Forensic Analysis

**What it is:** PrimeIntellect-ai/prime-agent (MIT, ~6,600 stars, released 2026-08-05 — 3 days old).

**Architecture:** RLM (Recursive Language Model) harness. Single tool surface: persistent IPython kernel. Sub-agents = Python function calls inside the kernel. State persists as Python variables across turns and context compaction. A daemon keeps sessions alive. "Continual Harness" self-improves prompts, skills, and subagent definitions from trajectory.

**ARC-AGI-3 result (95.5% with Opus 5):** Proves frontier benchmark capability on abstract reasoning puzzles. Does NOT prove: production reliability, Windows desktop control, task graph management, durable execution, or multi-provider routing. The benchmark is a pattern-recognition test, not an agent evaluation.

**Windows/API:** No evidence of native Windows support or headless REST API. No TS SDK.

**Verdict for Atlas:**

| Overlap Area | Replace Atlas Component? |
|-------------|------------------------|
| Task execution | NO VALUE — IPython kernel is not a task graph |
| Code generation | WRAP BELOW — could be a coding executor under Atlas |
| Desktop/computer use | NO VALUE — not designed for this |
| Memory/persistence | NO VALUE — Python variables, no durable state |
| Model routing | NO VALUE — single model (Opus 5) |
| Self-improvement | USE FOR RESEARCH — Continual Harness concept interesting |

**Bottom line:** Prime Agent is 3 days old, benchmark-optimized, and solves a different problem than Atlas. Not a replacement candidate. Potentially interesting as a research executor for specific abstract-reasoning tasks. Do not adopt until 6+ months of production evidence exists.

## 11. Migration Risks

1. **Cline SDK adoption** — replaces executor, but Atlas must retain authority above it. Risk: Cline updates break Atlas's tool governance. Mitigation: pin version, wrapper adapter.
2. **LiteLLM supply chain** — March 2026 supply-chain attack (v1.82.7-8), two April CVEs. Mitigation: pin, audit, self-host.
3. **Graphiti Neo4j dependency** — adds database server to local stack. Mitigation: use Cognee (SQLite+Kuzu) as lighter alternative.
4. **Agent-S model requirements** — needs UI-TARS-1.5-7B for grounding. GPU required for real-time. Mitigation: cloud inference or queue-based.
5. **OpenCode fork risk** — main repo archived. Mitigation: use Cline SDK instead.
6. **browser-use Python-only** — Atlas brain is TypeScript. Mitigation: subprocess call or HTTP bridge.
7. **Hatchet Docker dependency** — all durable workflow engines need Docker/WSL2 on Windows. Mitigation: keep custom exec-graph, defer migration.
8. **Memory index as second authority** — Graphiti could drift from canonical files. Mitigation: one-way index, file-based remains sole write authority.
9. **Infisical operational overhead** — another server to maintain. Mitigation: start with Infisical CLI (no server), upgrade later.
10. **Cedar immaturity for MCP** — reference architecture is July 2026, production evidence thin. Mitigation: defer until MCP auth spec stabilizes.

## 13. What Evidence Would Reverse the Recommendation

The INTEGRATE recommendations above would be reversed if:

- **Cline SDK** loses active maintenance (>90 days without release), or introduces a breaking license change
- **browser-use** benchmark results are shown to be cherry-picked (independent reproduction fails on Atlas-relevant tasks)

- **LiteLLM** has another supply-chain incident with >7 day response time
- **Agent-S / UFO2** Windows support is broken in practice (tested but fails on Atlas's actual machine)
- **Arize Phoenix** Elastic License 2.0 is determined to conflict with Atlas's distribution model

Each INTEGRATE decision should be re-evaluated after 6 months or after the first production incident with the adopted component.

The MUST_OWN list would shrink only if:
- An OSS project ships an equivalent CEO-intent parser with ADHD-aware multi-language support (unlikely)
- The emotion engine (PAD) proves to have zero impact on user experience (requires A/B test)
- An external task authority achieves the same deterministic verification guarantees Atlas requires
