## Waves — sequential, suite green between waves

**Wave A — P1.1 migrations as code (model: opus).** Requirement: `db/migrations/` becomes the complete,
ordered, from-zero definition of every table, RPC, index and RLS policy the code touches. An authoritative
sweep (file:line receipt per object) drives the set; existing 001/002 stay untouched (they may be live);
new numbered migrations add everything missing; the stray llm_spend files are superseded by a numbered
migration and marked deprecated in place (not deleted — they may match live state). Every table gets RLS.
A machine-readable manifest `db/migrations/MANIFEST.md` maps code-reference → migration file.
Acceptance: sweep table complete (every referenced object has a migration home) · **migrations apply cleanly
from zero to a disposable local Postgres (Docker) in order** — an executed receipt, not a claim · full suite green.

**Wave B — P1.3 restore drill (model: opus).** Requirement: a repeatable drill script
(`scripts/restore-drill.mts` or .ps1) that: stands up a scratch Postgres container → applies ALL migrations
in order → asserts every table/RPC/policy from the Wave A manifest exists → runs the closest available
agent smoke against scratch (at minimum: the queue enqueue/claim/sweep RPC round-trip with a fake row, and
the spend-receipt table write/read) → tears down. The drill RUNS in this wave and its log is committed as
`docs/atlas-cto/RESTORE-DRILL-RECEIPT-2026-07-28.md`. A backup that was never restored is not a backup;
a drill that never ran is not a drill.
Acceptance: drill executes end-to-end on this machine with exit 0 · receipt committed · rerunnable (idempotent
container naming, cleans up after itself) · full suite green.

**Wave C — P1.2 backup job (model: opus).** Requirement: `scripts/backup-atlas.mts` producing one dated
archive containing (a) logical export of the live tables from the manifest (runtime creds from env by NAME
only; skips gracefully with a clear message when env is absent) and (b) the local state dirs (exec-graph,
goal-budgets, evidence, spend receipts, runner state). Destination pluggable via `ATLAS_BACKUP_DIR`;
default outside the repo (`~/AtlasBackups`). Retention: keep last N (default 14), never delete anything
outside its own dated archives. A `docs/runbooks/backup.md` documents scheduling it via Windows Task
Scheduler (command provided for the operator; NOT auto-registered — machine changes are operator taps).
Acceptance: a real local run produces an archive with the state dirs (DB part exercised only if env
present — record which) · restore path proven: unpack + the Wave B drill consumes the DB export → that
combined proof appended to the drill receipt · full suite green.
Named open gate (CEO): the "agent cannot delete its own backups" hardening requires an off-machine
destination decision (his call, standing gate-queue item). Until then backups are local-only — recorded honestly.

**Wave D — P1.4 bootstrap runbook (model: sonnet).** Requirement: `docs/runbooks/bootstrap.md` — from
bare Windows machine + empty database to a running Atlas (cloud bot + local runner), using only this repo:
prerequisites, env var NAMES table (no values) with where each is set, migration apply order, backup/restore
usage, runner install + autostart, verification commands with expected outputs. Every command in it must be
one the executor dry-ran during A-C or marks explicitly UNTESTED.
Acceptance: doc exists · every command labeled tested/UNTESTED truthfully · cross-references A-C artifacts · registered in `ATLAS-STATE-NOW.md`.
