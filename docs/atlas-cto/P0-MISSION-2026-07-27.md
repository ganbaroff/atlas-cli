## Waves — one executor run each, sequential, suite green between waves

**Wave A — P0.4 durable spend cap.** `src/atlas/spend-tracker.ts` keeps the daily counter only in
process memory (lines ~84/95/113). Requirement: at process start the daily counter is rehydrated
from the on-disk spend receipts for the current day (reader already exists: `readSpendReceipts`).
Acceptance: a test simulates stop/restart (fresh module state) and proves the counter continues
from the persisted value, not zero; a same-day receipt written before "restart" is counted after
it; a yesterday-receipt is not. Full suite green.

**Wave B — P0.3 actor-scoped writes.** `src/tools/write-file.ts` reads `ATLAS_AGENT_ID` but uses it
only for audit logging. Requirement: file writes become actor-aware the way `shell.ts` already is —
when the actor is `autonomy`, writes resolve only under an allowlisted workspace root (env
`ATLAS_WORKSPACE_ROOT`, default = repo root); path traversal out of the root refuses with a
structured reason. Non-autonomy actors keep current behavior. Same treatment for the write path of
any sibling fs tool that shares the guard. Acceptance: autonomy write inside root ⇒ ok; autonomy
write outside root (absolute and `../` forms) ⇒ refused with reason; non-autonomy unaffected;
existing fs-guard sensitive-path rules still hold; full suite green.

**Wave C — P0.2 red-line coverage, keyword floor.** `src/goal-runner/red-line.ts` matches
substrings and the five documented Russian gap phrasings pass through. Requirement: root-based
Cyrillic matching so every category (secrets / payment / prod-db / merge / delete / money) blocks
its Russian forms across inflection; the five documented gap phrasings become named test cases and
block. Matching stays deterministic and offline. Acceptance: all five gap phrasings ⇒ blocked;
prior English coverage unchanged (regression tests); benign Russian commands (e.g. «проверь статус»,
«прочитай файл») still pass; full suite green.

**Wave C2 — P0.2 second classifier (additive vote).** A cheap free-tier model may add a block,
never remove one. Requirement: called inside the red-line gate; transport/classifier error ⇒ the
row is refused (the gate's existing throw⇒blocked behavior is the authority); env kill-switch
`ATLAS_REDLINE_LLM=0` disables the classifier leaving the keyword floor in force. Consequence
accepted in writing: with the classifier enabled and all free providers down, rows are refused
until the operator flips the kill-switch — safety over availability. Acceptance: mocked classifier
"block" vote refuses a row that keywords alone would pass; mocked classifier error refuses;
kill-switch set ⇒ keyword-only behavior; no live network in tests.

**Wave D — P0.1 work-order authenticity.** Queue rows gain an authenticity code: HMAC over
`{command, chat_id, ts, nonce}` with a key read from env `ATLAS_QUEUE_SIGNING_KEY` (name only —
value is CEO-set, never in code or chat). Producer (`enqueueRemote` path) signs when the key is
present; signature travels in `payload.sig` (+`ts`,`nonce`) — no schema change. Runner verifies
**before** the red-line check. Enforcement is staged: runner with key set ⇒ refuse rows that are
unsigned, mis-signed, older than 24h, or replaying a seen nonce (bounded file-backed nonce ledger);
runner without key ⇒ accept with a loud once-per-boot warning and a `runner status` line saying
enforcement is off. Acceptance: signed row passes; each refusal class has a test with its receipt
reason; no-key mode accepts and warns; full suite green.
