structured reason. Non-autonomy actors keep current behavior. Same treatment for the write path of
any sibling fs tool that shares the guard. Acceptance: autonomy write inside root ⇒ ok; autonomy
write outside root (absolute and `../` forms) ⇒ refused with reason; non-autonomy unaffected;
existing fs-guard sensitive-path rules still hold; full suite green.

**Wave D — P0.1 work-order authenticity.** Queue rows gain an authenticity code: HMAC over

### Two real defects found during activation (recorded, not fixed here)

1. **Stale-`dist` runner.** The autostart scheduled task runs `dist\cli.js`, and nothing in the merge/deploy path rebuilds `dist`. The local runner had been executing a build that predated `queue-auth` entirely. Fixed by hand this run (`npm run build` + task restart); the **systemic** fix (rebuild on start, or a freshness check in `runner start`) belongs in P3 observability.
2. **`authEnforcement` in `runner status` is misleading.** `atlas-runner.ts:328` computes it from `getSigningKey()` **in the reading process**, so any caller that does not load `.env` reports `off` regardless of the runner's real state. It describes the reader, not the runner. Real state must be proven through the queue (as above) until fixed.

### DEFECT RESOLUTION — 2026-07-29

Both source defects have a recovered, locally verified patch. Runtime closure
is still OPEN: the observed `AtlasRunner` scheduled task still invokes
`node dist\cli.js runner start --interval 20` directly. Switching it to the
wrapper and proving one live restart belongs to later authorized cutover.

**Defect 1 — stale `dist`.** Both defences from the brief, deliberately:

- `src/atlas/build-freshness.ts` (new). Compares the mtime of the `dist/cli.js`
  actually being executed against the newest non-test file under `src/`.
  `runner start` prints a `REFUSING TO START` block naming the offending source
  file and exits `1` — a loud refusal, never a silent stale run. Override is
  explicit and logged: `--allow-stale-dist` / `ATLAS_ALLOW_STALE_DIST=1`.
- `scripts/start-runner.cmd` (new). Intended scheduled-task wrapper; it
  rebuilds before launching and redirects everything to
  `%USERPROFILE%\.atlas\runner-autostart.log`. A failed build is not swallowed —
  it hands off anyway and lets the freshness gate refuse.

The gate reports `unknown` and stays inert where it cannot be trusted (running
under `tsx`, or a deploy that ships no `src/`) — exclusions are pinned by test.
Test edits deliberately do not count as build inputs; a gate that cries wolf
gets ignored, which is the failure mode being fixed.

**Defect 2 — misleading liveness field.** `authEnforcement` is no longer derived
in the reading process. The runner declares its own state into the instance
lease at startup (`annotateInstanceLease` in `src/atlas/instance-lease.ts`,
called from `recordRunnerStartState`), and `describeRunnerLiveness` reports the
value **from the lease**. Annotation ownership requires the
acquisition-specific instance ID plus PID, so a read-only second instance cannot
overwrite the real writer's declaration. Failed self-declaration refuses startup
before the polling loop. A fresh unmarked non-runner lease reports non-success
`occupied` and emits no auth or build fields. The same channel now carries a
build stamp, so `runner status` shows *which build* is live.
