## Shared-memory safe-write protocol (Track E, 2026-07-17)

**Problem.** `memory/atlas/*.md` (this file, `lessons.md`, `.claude/breadcrumb.md`) is git-tracked and branch-dependent. `C:\Projects\VOLAURA` is a single shared working directory — if a concurrent VOLAURA-product session has it checked out to a different branch with live uncommitted product-code edits (confirmed this happened: the directory was on `fix/pr-169-rubric-repair-r2` with foreign uncommitted `apps/web/...` edits while this file's history lives on `fix/pr-169-rubric-repair`), a Local-CTO/Atlas session can neither safely `git checkout` there (would need to stash/discard someone else's live work) nor read/write this file directly from the wrong branch.

**Note — `memory/shared-bus/*` is a different case.** Checked directly: `git worktree add` on this branch materializes zero files under `memory/shared-bus/` (verified — the directory doesn't exist in the worktree at all), even though `memory/shared-bus/LANE-RULES.md` etc. are readable from the actual main working directory. This means `shared-bus/` is **not part of the git-tracked tree** — it lives outside version control (symlink/mount, per ANUS's own `ATLAS-CANON.md` describing it as a symlink target). The protocol below applies only to git-tracked `memory/atlas/*` files; `shared-bus/` doesn't have the branch-collision problem, but it also can't be reached from an isolated worktree — a session needing to write there safely needs a different mechanism (not solved here, flagged as future work if it becomes a real contention point).

**Protocol (git-tracked `memory/atlas/*` only), preferred solution #1 from the Track E brief:**
